# 44 Milady — Milestone 10: Release hardening + public Devnet

Milestone 10 turns the M1–M9 source implementation into a releaseable Solana protocol.

## Security/admin hardening

Protocol administration now uses two-step rotations:

1. current authority proposes a new authority;
2. only the proposed signer can accept;
3. the pending address is cleared after acceptance.

Emergency authority rotates independently. Treasury changes are explicit and evented.

The authority field is a generic signer address, so it can be controlled by a multisig execution system rather than a single hot wallet. The two-step transfer also prevents an accidental one-transaction handoff to a mistyped address.

## Key policy

Never commit:

- deployer private keys;
- program keypairs;
- JSON seed arrays;
- wallet mnemonics.

The stable program keypair lives under `target/deploy/` locally (already gitignored) and must be backed up securely. The Devnet GitHub workflow consumes it only through an environment secret.

Required GitHub environment secrets for `devnet`:

- `DEVNET_DEPLOYER_KEYPAIR_JSON`
- `PROGRAM_KEYPAIR_JSON`
- `DEVNET_CONFIG_JSON`

The workflow verifies that the public key derived from `PROGRAM_KEYPAIR_JSON` exactly matches both `declare_id!` and `Anchor.toml`. A mismatch blocks deployment.

## Canonical program ID

Before the first public deployment:

```bash
export ANCHOR_WALLET=/secure/devnet-deployer.json
./scripts/devnet/prepare-program.sh
```

This creates the stable program keypair under `target/deploy/`, runs `anchor keys sync`, and rebuilds the program. Before SBF build, install platform-tools v1.57 with `cd programs/forty_four_milady && cargo build-sbf --tools-version v1.57`; the older Cargo bundled with Solana 2.1 cannot parse current Edition-2024 transitive crates.

Commit only the resulting public program ID changes. Back up the private program keypair separately.

## Devnet configuration

Copy:

```bash
cp config/devnet.example.json config/devnet.local.json
```

Fill the real 32-byte Pyth feed IDs and Solana Devnet price-feed account addresses for NVDA, AAPL, SPY and TSLA before bootstrap.

The protocol validates the receiver program owner, discriminator, full verification level, feed ID, freshness, positive price and confidence interval on-chain.

## Bootstrap

`npm run devnet:bootstrap` performs an idempotent setup:

- initializes ProtocolConfig;
- creates mock USDG/NVDAx/AAPLx/SPYx/TSLAx mints;
- sets the protocol PDA as mint authority;
- registers faucet assets;
- registers collateral markets;
- initializes the USDG lending pool;
- configures liquidation policy;
- writes only public addresses to `deployments/devnet.local.json`.

Mock assets have no value.

## Verification

`npm run devnet:verify` checks:

- program account exists and is executable;
- IDL program ID equals deployment manifest;
- protocol version is M10 or newer;
- USDG pool references the expected mint;
- all mock mints exist;
- all configured markets exist and are enabled.

## Live E2E

`npm run devnet:e2e` executes a real Devnet happy path:

1. claim mock USDG;
2. supply USDG;
3. claim collateral;
4. initialize credit account;
5. deposit collateral;
6. refresh health from configured Pyth account;
7. enable borrowing;
8. borrow a bounded amount of USDG;
9. repay MAX;
10. assert final debt is zero.

The test deliberately derives its borrow amount from the on-chain risk snapshot instead of hard-coding a dollar amount.

## Adversarial checks

`npm run test:adversarial` executes 50,000 deterministic state transitions across:

- deposits/supply;
- borrowing;
- repayment;
- price shocks;
- liquidation.

It checks monotonic debt reduction for repay/liquidation, LTV enforcement for new debt, non-negative accounting and collateral seizure direction.

These model checks supplement—not replace—Solana integration tests and an external audit.

## Monitoring

`npm run devnet:monitor` continuously reports:

- pause state;
- borrowing/liquidation switches;
- physical USDG vault balance;
- total supplied/borrowed;
- protocol reserves;
- insurance reserves;
- bad debt;
- utilization;
- borrow/supply APR.

It emits explicit stderr alerts for pause state and uncovered bad debt.

## CI gates

Every pull request now runs:

- release preflight;
- structure/model/keeper/adversarial tests;
- Next.js production build;
- `cargo fmt --check`;
- `cargo check`;
- Rust tests;
- Anchor SBF build with Anchor 0.31.1, Solana 2.1.0 and pinned platform-tools v1.57 (needed for Edition-2024-compatible transitive crates).

## Manual public deployment workflow

The workflow `44 Milady Devnet Release` is intentionally manual. It does not generate or store a new program keypair.

After the three Devnet environment secrets exist, run the workflow from GitHub Actions. It builds, deploys, bootstraps and verifies the protocol, with an optional live E2E run.

## Credential gate

The repository can implement and test every release step, but it cannot sign a Devnet deployment without a funded signer and the stable program keypair.

Therefore the correct release status before those secrets exist is:

**M1–M10 source/release engineering complete; public Devnet transaction pending credentials.**

Do not label the protocol Devnet-live until `devnet:verify` passes against an executable on-chain program.
