# 44 Milady — Milestone 9: Liquidation + solvency protection

Milestone 9 makes unhealthy debt enforceable and defines what happens when collateral is not enough.

## Liquidation threshold

A credit account becomes liquidatable when:

```
health factor <= 1.0
```

Health is recomputed from fresh Pyth data inside the Solana program before any liquidation can execute.

A keeper's cached health value is discovery-only and never authorizes collateral seizure.

## Close factor

The pool has a configurable `liquidation_close_factor_bps`.

Default:

```
50% = 5,000 bps
```

For a $4,000 synchronized debt position, one liquidation can repay at most $2,000 before collateral-value caps are applied.

The authority can change the close factor between 1 and 10,000 bps or disable liquidations independently.

Emergency protocol pause does not automatically disable liquidations, because liquidation is a risk-reducing action. The dedicated liquidation switch is the explicit kill switch.

## Market liquidation bonus

Each collateral market already stores its own `liquidation_bonus_bps`.

Example:

```
liquidator repays: $1,000 USDG
bonus:              5%
collateral value:   $1,050
```

The actual collateral token amount is derived from the same fully verified Pyth PriceUpdateV2 data used by the risk engine.

## Liquidation amount caps

The program chooses the minimum of:

1. liquidator's requested maximum;
2. synchronized borrower debt;
3. global close-factor cap;
4. amount supportable by the selected collateral after liquidation bonus.

This means the keeper can submit a generous maximum while the program safely determines the actual repay amount.

## Liquidation flow

```
fresh Pyth portfolio valuation
        ↓
health <= 1.0?
        ↓ yes
sync interest
        ↓
liquidator USDG → lending-pool vault
        ↓
borrower debt decreases
        ↓
selected collateral + bonus → liquidator
        ↓
pool total borrowed decreases
        ↓
health / rate cache updated
```

The selected collateral market can still be liquidated if that market has been disabled for new borrowing/deposits.

## Keeper

`keeper/` contains the Devnet liquidation service.

The keeper:

- polls all `CreditAccount` PDAs;
- filters cached health <= 1.0;
- prioritizes worst health first, then larger debt;
- loads every collateral market for the borrower;
- maps market feed IDs to fresh Pyth PriceUpdateV2 accounts;
- supplies the complete remaining-account set;
- calculates the close-factor maximum;
- submits `liquidate`.

The keeper is **dry-run by default**.

Required runtime configuration is documented in `keeper/README.md`.

Even when the keeper makes a mistake or sees stale cached state, the on-chain liquidation instruction rechecks:

- fresh Pyth owner/discriminator/verification/feed/freshness/confidence;
- whole-account liquidation health;
- close factor;
- selected collateral amount;
- liquidation bonus;
- token mints;
- PDA ownership;
- pool debt accounting.

## Dedicated insurance reserve

Anyone may send real USDG into the pool through:

```
fund_insurance_reserve(amount)
```

This:

- transfers physical USDG into the canonical liquidity vault;
- increases `insurance_reserve_usdg`;
- adds first-loss capital without creating a supplier claim.

Insurance funding is allowed during protocol pause because it reduces risk.

## Bad debt

If all collateral has been exhausted but synchronized debt remains, the position can enter bad-debt resolution.

`absorb_bad_debt` requires:

- debt > 0;
- **zero recorded collateral**.

The loss waterfall is:

```
1. protocol interest reserves
2. dedicated insurance reserve
3. uncovered bad debt
```

Example:

```
remaining debt:          $500
protocol reserves:       $100
insurance reserve:       $200

reserve coverage:        $100
insurance coverage:      $200
uncovered bad debt:      $200
```

The borrower's debt is then cleared and the unrecovered deficit is tracked in `bad_debt_usdg`.

## Pool accounting with losses

Net pool assets are modeled as:

```
total supplied claims
+ protocol reserves
+ insurance reserve
- bad debt
```

Available liquidity is:

```
net pool assets - total borrowed
```

This preserves the physical-cash invariant when a loan is written off.

## Recapitalization

A treasury, backstop fund or external insurer can repair an uncovered deficit with:

```
recapitalize_bad_debt(amount)
```

The instruction:

- transfers real USDG into the liquidity vault;
- decreases `bad_debt_usdg` by the same amount;
- does not mint supplier claims.

It cannot recapitalize more than the currently recorded deficit.

## M9 acceptance scenario

1. Lender supplies 10,000 USDG.
2. Borrower deposits tokenized collateral and borrows 3,000 USDG.
3. Collateral price drops.
4. Fresh Pyth health falls below 1.0.
5. Keeper detects the account.
6. Liquidator repays up to the 50% close factor.
7. Liquidator receives collateral plus the market bonus.
8. Repeat liquidation if necessary.
9. If collateral is exhausted with debt remaining, call `absorb_bad_debt`.
10. Protocol reserves absorb the first part of the loss.
11. Insurance reserve absorbs the next part.
12. Any remaining deficit becomes `bad_debt_usdg`.
13. A treasury/insurer sends USDG through `recapitalize_bad_debt` to restore solvency.
