# 44 Milady — Milestones 2–5

This document describes the Devnet collateral/risk layer implemented before USDG borrowing is enabled.

## M2 — Devnet markets and faucet

On-chain components:

- `MarketConfig` PDA derived from `['market', collateral_mint]`.
- Configurable Pyth feed id, LTV, liquidation threshold, liquidation bonus, confidence limit, oracle age, supply cap and future debt ceiling.
- `FaucetConfig` PDA per mint.
- `FaucetClaim` PDA per wallet + mint, including cooldown and lifetime claimed amount.
- `claim_faucet` mints using the protocol PDA as mint authority.

Mock Devnet mints should be created for:

- USDG — 6 decimals
- NVDAx — 6 decimals
- AAPLx — 6 decimals
- SPYx — 6 decimals
- TSLAx — 6 decimals

The mock mints have no economic value. Their mint authority must be transferred to the protocol PDA before faucet claims can succeed.

## M3 — Collateral custody

- One `CreditAccount` PDA per wallet.
- Up to 8 collateral markets per account.
- One program-owned token vault PDA per credit account + market.
- Deposit uses `transfer_checked` from the user token account into the vault.
- Withdrawal signs with the credit-account PDA.
- Market `total_deposited` accounting is updated atomically.
- Supply caps and owner/mint/PDA constraints are enforced on-chain.

## M4 — Pyth valuation

44 Milady consumes `PriceUpdateV2` accounts from the Pyth Solana Receiver.

Each market stores its expected 32-byte feed id. During valuation the program verifies:

1. the market account is owned by 44 Milady;
2. the price update is owned by the Pyth Receiver program;
3. the update contains the market's configured feed id;
4. the update is not older than `max_price_age_secs`;
5. price is positive;
6. confidence width is no larger than the configured basis-point limit.

Token amounts and Pyth exponents are normalized into **USD micro-units (1e-6 USD)** using integer arithmetic only.

## M5 — Portfolio risk / health

`refresh_health` receives ordered remaining-account pairs for every collateral position:

```
[MarketConfig, PythPriceUpdate, MarketConfig, PythPriceUpdate, ...]
```

It computes:

- total collateral value;
- weighted initial borrowing limit;
- weighted liquidation capacity;
- health factor.

Health factor is represented in basis points:

```
HF_bps = liquidation_capacity_usd_micro * 10_000 / debt_usdg
```

When debt is zero, health is stored as `u64::MAX`.

The debt field is intentionally present now so Milestone 6 can add borrowing without redesigning the credit account. USDG will use 6 decimals, making raw USDG debt equal to USD micro-units.

## Withdrawal safety

When debt is non-zero, `withdraw_collateral` recomputes portfolio health after reducing the collateral balance and rejects the transaction unless health remains above 1.0 (`> 10_000 bps`). This is inactive for zero-debt M2–M5 accounts but is already wired for M6.

## Oracle client requirement

The frontend/keeper must supply fresh Pyth updates. Pyth's upgraded Solana flow uses the Solana Receiver and Hermes. Since August 26, 2026, Hermes access requires a Pyth API key. Do not embed that key in the browser bundle; proxy or sponsor updates from a server/keeper.
