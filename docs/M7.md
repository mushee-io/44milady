# 44 Milady — Milestone 7: Interest engine

Milestone 7 turns static USDG debt into a time-aware lending market.

## Utilization curve

The USDG pool uses a piecewise borrow-rate model:

```
if U <= kink:
  borrow APR = base + slope1 * U / kink
else:
  borrow APR = base + slope1 + slope2 * (U - kink) / (1 - kink)
```

Recommended Devnet configuration:

- base rate: 2.00%
- slope 1: 8.00%
- kink: 80%
- slope 2: 50.00%
- reserve factor: 10%

That produces roughly:

- 0% utilization → 2% borrow APR
- 80% utilization → 10% borrow APR
- 90% utilization → 35% borrow APR
- 100% utilization → 60% borrow APR

The protocol caps configured maximum borrow APR at 1000%.

## Supply rate and APY

Supplier APR is derived from borrower revenue:

```
supply APR =
  borrow APR
  × borrowed / supplied
  × (1 - reserve factor)
```

The on-chain program stores APR in basis points. The SDK exposes an APY helper for UI display using a configurable compounding frequency. APY is presentation-only; protocol accounting is index based.

## Global indexes

The pool maintains:

- `borrow_index_e18`
- `supply_index_e18`

Both start at `1e18`.

Borrowers and suppliers store their own index snapshots. On interaction, the account is synchronized against the current global index rather than iterating over every user.

This makes accrual O(1) regardless of user count.

## Interest accrual

Anyone may call `accrue_interest`.

Accrual also happens automatically before:

- supply;
- supplier withdrawal;
- borrow;
- borrower interest sync;
- supplier interest sync;
- health refresh;
- collateral withdrawal;
- interest-model updates.

Gross borrower interest is split into:

```
supplier interest = gross interest - protocol reserve
protocol reserve  = gross interest × reserve factor
```

The pool then updates:

- total borrowed;
- total supplied claim;
- protocol reserves;
- borrow index;
- supply index;
- cached Borrow APR;
- cached Supply APR.

## Fractional-interest defense

USDG has 6 decimals. Very frequent accrual calls could otherwise repeatedly round sub-micro-unit interest to zero.

44 Milady stores `borrow_interest_remainder` and carries the fractional numerator into future accruals. Calling accrual every second therefore cannot suppress interest.

## Balance-sheet accounting

After interest accrual:

```
assets = physical cash + borrower debt
liabilities = supplier claims + protocol reserves
```

The protocol derives accounting liquidity as:

```
available liquidity =
  total supplied + protocol reserves - total borrowed
```

Token transfers additionally check the real USDG vault balance.

## Borrower safety

A borrower debt balance is synchronized to the latest borrow index before:

- taking another loan;
- refreshing health;
- withdrawing collateral.

This means a user cannot avoid accrued interest and then withdraw collateral using an old debt balance.

## Protocol reserves

The reserve counter records the protocol share of interest. M7 only accrues the reserve claim.

Physical reserve withdrawal is intentionally deferred until repayment exists in M8, because interest is an account receivable until borrowers return USDG to the vault.

## M8 handoff

Milestone 8 adds repayment. Repayment will:

1. accrue the pool;
2. synchronize borrower debt;
3. accept USDG back into the pool vault;
4. reduce borrower debt and total borrowed;
5. make accrued supplier yield and protocol reserves physically liquid.
