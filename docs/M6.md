# 44 Milady — Milestone 6: USDG liquidity + borrowing

Milestone 6 turns the collateral/risk core into a real credit market.

## New on-chain accounts

### LendingPool

PDA:

```
["lending_pool", usdg_mint]
```

Tracks:

- canonical USDG mint;
- protocol-owned liquidity vault;
- total supplied USDG;
- total borrowed USDG;
- optional global borrow cap;
- borrowing enabled/disabled state;
- reserve factor for Milestone 7;
- 1e18 borrow/supply indexes reserved for Milestone 7.

USDG must use exactly 6 decimals. This keeps one raw USDG unit equal to one USD micro-unit used by the risk engine.

### Liquidity vault

PDA token account:

```
["liquidity_vault", lending_pool]
```

Its token authority is the LendingPool PDA. User wallets never receive signing authority over pool custody.

### SupplierPosition

PDA:

```
["supplier", lending_pool, supplier]
```

Tracks each lender's principal USDG and the supply-index snapshot needed by the next interest milestone.

## Instructions

### initialize_lending_pool

Protocol authority creates the USDG pool and canonical liquidity vault.

Initialization starts with borrowing disabled. The authority must explicitly enable it through `update_lending_pool` after liquidity and risk configuration are ready.

### update_lending_pool

Protocol authority may:

- enable/disable new borrowing;
- set the global borrow cap;
- set the reserve factor reserved for M7.

The borrow cap cannot be reduced below outstanding pool debt.

### supply_usdg

A lender transfers USDG into the pool vault.

Atomic accounting updates:

```
supplier_position.principal += amount
pool.total_supplied += amount
```

Interest is intentionally not credited yet; Milestone 7 activates the supply index.

### withdraw_supplied_usdg

A lender may withdraw principal only when all three conditions hold:

1. the supplier position owns enough principal;
2. protocol accounting shows enough idle liquidity;
3. the token vault physically contains enough USDG.

Idle liquidity is:

```
total_supplied - total_borrowed
```

This prevents lenders from withdrawing USDG that is currently held by borrowers.

### borrow_usdg

Borrowing uses the M4/M5 Pyth + portfolio risk engine.

The borrower supplies ordered risk accounts:

```
[MarketConfig, PythPriceUpdate, MarketConfig, PythPriceUpdate, ...]
```

The instruction:

1. verifies the protocol is not paused;
2. verifies borrowing is enabled;
3. verifies the pool has enough idle and physical USDG;
4. enforces the global borrow cap;
5. recomputes collateral value from fresh Pyth data;
6. calculates the user's weighted initial borrow limit;
7. rejects `current_debt + requested_amount > borrow_limit`;
8. rejects any immediately liquidatable post-borrow position;
9. transfers USDG from the pool PDA vault to the borrower;
10. persists debt and a fresh risk snapshot.

No frontend number is trusted for solvency.

## Withdrawal hardening

M6 tightens collateral withdrawal. A borrower may only remove collateral when the resulting account remains:

- within the initial LTV borrowing limit; and
- above the liquidation health threshold.

This prevents a user from borrowing safely and then withdrawing collateral into an over-LTV state.

## Schema preparation for M7

M6 adds these fields before Devnet deployment so M7 does not require an account migration:

- `LendingPool.borrow_index_e18`
- `LendingPool.supply_index_e18`
- `LendingPool.last_accrual_ts`
- `LendingPool.reserve_factor_bps`
- `CreditAccount.borrow_index_snapshot_e18`
- `SupplierPosition.supply_index_snapshot_e18`

They start at 1e18 and remain static until M7 activates interest accrual.

## Deliberately not in M6

- borrower interest;
- supplier APY;
- repayment;
- liquidation;
- bad debt;
- protocol reserves.

Those belong to M7–M9.

## Acceptance flow

A useful Devnet M6 test is:

1. Wallet A claims 10,000 mock USDG.
2. Wallet A supplies 10,000 USDG.
3. Wallet B claims/deposits NVDAx + SPYx.
4. Longbow/44 Milady values collateral with fresh Pyth updates.
5. Wallet B borrows 1,000 USDG.
6. Pool accounting becomes 10,000 supplied / 1,000 borrowed / 9,000 idle.
7. Wallet A cannot withdraw more than 9,000 while that debt remains outstanding.
8. Wallet B cannot borrow above its weighted LTV even if the pool has excess cash.

Repayment arrives in Milestone 8; for now M6 proves real collateral-backed USDG issuance from lender liquidity.
